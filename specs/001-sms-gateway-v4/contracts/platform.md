# Platform integration contract

Reference code: `../go-tangra-notification-v4/internal/app/`, `pkg/notificationmanifest/manifest.go`, `../go-tangra-portal-v4/sdk/pkg/gatewayclient/`, and `../go-tangra/docs/{security-model,frontend}.md`.

- Service/module name is `sms-gw`, identity `spiffe://<configured-trust-domain>/svc/sms-gw`. Mesh identity and expected callee are verified by V4 framework, with deny-by-default operation policy. Public edge TLS has separate keys, trust roots and lifecycle.
- Embed Freya config; initialize repositories/secrets, identity and App; mount management handlers on App.HTTP; use pooled SDK clients for auth/portal/LCM; register after Ready and advertise actual mesh endpoints. Registration lease recovery, auth role/permission refresh and graceful deregistration are cancellable workers.
- `pkg/smsgwmanifest/manifest.go` declares display name/version, prefix, permissions, roles, abilities, navigation and routes derived from OpenAPI `x-freya-permission`. Permission declarations and handlers must match exactly. No legacy descriptor.bin registration or x-md-global role trust.
- Module serves federated assets at `/ui/`; portal relay is `/m/sms-gw/`, with `mf-manifest.json` and only declared exports. Use `/sms-gw/{providers,templates,api-clients,blocks,messages,dashboard}` navigation and a permission-gated manual send drawer. Do not claim `/ui` as the module API prefix.
- UI uses @go-tangra/ui, shared API client, write schemas and platform layout. Federation singletons use Vue 3.5, Router 5, Pinia 4, CASL ability 7/vue 3, Zod 4 and kit/forms/api 4; production shares use import:false and kit/Zod strict versions per local frontend guide. Copy exact exported route/nav shape from V4 contracts and test manifest against built remote; do not declare unimplemented header exports.
- Backend independently verifies operator tokens, tenant and permission. Gateway identity is a service caller, not proof of operator authority. Requests propagate request ID/trace context; sanitized audit records actor, tenant, operation, object and outcome.
- Internal health/readiness and metrics use framework administration/network policy. Readiness reflects database, config and identity; registration/dependency outages are reported explicitly and protected operations fail closed when verification cannot succeed. Optional monitoring and public certificate failures do not take healthy internal endpoints offline.
- Config separates mesh HTTP/gRPC/admin addresses from public HTTP/HTTPS, stores secrets as mounted/env references, documents legacy environment aliases and disallows conflicting identities. No production keys are committed. Docker UI package token enters through BuildKit secret.

Platform acceptance: auth permission registration, portal lease renewal/recovery, remote loading, direct backend deny cases, foreign tenant probes, forged identity headers, internal SVID rotation/expiry and cancellation/drain must all pass against the local V4 stack.
